## Work Order 0.7b — status (2026-08-26)

**Not closed. `eval/run_eval.py` was not run end-to-end, and no row has been added to the table above.**

The nine verified schemes were re-fetched under certificate verification (Work Order A1/A2), re-indexed into a real Postgres 18 + pgvector instance, and the golden set's `gold_quote` fields were corrected to be verbatim (Work Order A4 — see below). Against that real, verified corpus, retrieval that needs no external API was run directly (bypassing `eval/run_eval.py`'s full pipeline) and produced:

- **FTS Recall@5: 0.2632** (real — Postgres full-text search, 19/19 non-negative golden cases correctly resolved to a gold chunk after the whitespace-normalization fix below)

Two things block a real number for the rest of the harness's columns (Vector Recall@5, Hybrid Recall@5, Citation Precision, Faithfulness, Groundedness Rate), and both are missing credentials, not missing code:

- No `GEMINI_API_KEY` is configured anywhere in this environment, so `ingest/embedder.py` falls back to `MockEmbedder` — a deterministic hash-based vector, not a real semantic embedding. A Vector Recall number measured against it (0.2632, for reference) reflects the mock's keyword-overlap heuristic, not the actual embedding model, and is not meaningful as a baseline.
- No `GEMINI_API_KEY` is configured, so `api/llm/client.py` falls back to `MockLLMClient`. For any question whose normalized text matches a golden-set question, that client returns the case's own `gold_answer` **verbatim**, and its faithfulness-judge and groundedness-check code paths always return a perfect score. Running `eval/run_eval.py` in this state would produce Citation Precision / Faithfulness / Groundedness numbers indistinguishable in form from the synthetic 94%/100% voided above — the exact failure this re-baseline exists to fix. It was deliberately not run and nothing was appended here under that name.

**This is not the "first real baseline."** It is a partial, retrieval-only, honestly-labeled measurement. Closing 0.7b for real requires re-running `eval/run_eval.py` unmodified with a live `GEMINI_API_KEY` present, then appending that row here.

Two supporting fixes were made while investigating this, both narrow and reported in full to the reviewer:
1. `eval/golden/golden_set.yaml`'s `pm-jjby` annual-premium quote was replaced with a genuine verbatim prose span (`ingest/fetcher`/golden-set work order A4) — the old quote only "matched" a garbled table-extraction artifact.
2. `eval/run_eval.py::resolve_gold_chunk_ids` matched chunk text with a raw `ILIKE`, so a verbatim quote spanning a PDF line-wrap (preserved as a literal `\n` inside the stored chunk) silently failed to resolve to any chunk and was miscounted as out-of-corpus. Fixed to compare on whitespace-normalized text; this raised in-corpus resolution from 12/19 to 19/19 non-negative golden cases.
